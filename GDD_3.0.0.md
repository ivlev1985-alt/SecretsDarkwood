# GDD: Secrets of the Darkwood

**Версия документа:** 3.0.0
**Дата:** 2026-05-14
**Статус:** Черновик

## 1. Общая информация

**Название:** Secrets of the Darkwood (рабочее)
**Жанр:** Казуальный экшен / Выживание (Survivors-like)
**Платформа:** Yandex Games (HTML5)
**Ориентация:** Портретная (вертикальная)
**Управление:** PC — WASD/стрелки + мышь; Mobile — виртуальный джойстик
**Цель:** Создать масштабируемую основу с технической возможностью быстрого производства клонов через замену ассетов и JSON-конфигов без изменения кода.

## 2. Основная механика (Gameplay Core)

### 2.1. Игровой цикл

**Заставка → Главное меню:**

1. **Заставка** (логотип студии, 1–2 сек).
2. **Главное меню** с бонусом за ежедневное посещение (кнопка «Забрать бонус» активна раз в 24 ч).
3. **Подменю «Настройки»:** громкость эффектов, громкость музыки, выбор языка, настройка расположения элементов управления (джойстик слева/справа).
4. **Подменю «Магазин»:** покупка перманентных бонусов (см. п. 5.5 — отдельный JSON).
5. **Подменю «Лидеры»** (перемещено сюда, смещение на 1).

**Игровой цикл (внутри забега):**

1. **Старт** — персонаж в центре карты.
2. **Спавн** — первый спавн с задержкой по времени (игрок осваивает управление), либо по триггеру (нашёл и открыл сундук).
3. **Бой** — автоатака **тремя видами**:
   - **От персонажа к цели (целям)** — например, файрбол, цепь молнии.
   - **Вокруг персонажа в ограниченном радиусе** — например, кольцо холода.
   - **В определённой области с врагами** — огненная стена, смерч, вулкан.
4. **Прогрессия** — убийство врагов даёт опыт и/или монеты, которые падают на землю. Если упавшие монеты/опыт оказываются в радиусе подбора — подбираются. При наборе опыта — levelup, пауза, выбор 1 из 3 улучшений.
5. **Сундуки** — респаунятся за пределами видимости.
6. **Смерть** — экран результатов с единоразовым воскрешением за просмотр рекламы.
7. **Продолжение игры** либо выход в меню.

### 2.2. Управление

- **PC:** WASD / стрелки — движение. Мышь — навигация по меню.
- **Mobile:** виртуальный джойстик. По настройке — **слева или справа**. Шкалы HP/XP располагаются **с противоположной стороны** от джойстика.
- **Требование Yandex:** игра полностью управляется жестами/мышью без системных контекстных меню.

## 3. Архитектура «Config-Driven» (Ядро системы клонирования)

### 3.1. Принципы

**Цель:** сделать клонирование максимально простым. Любой клон игры делается заменой ассетов и правкой JSON-конфигов. Код не трогается.

**Три уровня гибкости:**

1. **Замена ассетов с сохранением имён** — код не трогается, конфиги не трогаются. Просто заменить PNG/MP3 в `assets/`.
2. **Замена ассетов с переименованием** — правится только путь в конфиге (`sprite`, `sfx_*`). Код не трогается.
3. **Добавление новой сущности** (монстр, заклинание, эффект, сундук) — добавляется блок в конфиг. Код не трогается, если сущность использует существующий `type`/`movement_type`/`behavior`. Если нужен новый тип поведения — добавляется 1–2 строки в реестр типов (см. п. 3.4).

**Приоритет при разработке:** все решения принимаются с оглядкой на то, чтобы клонирование было как можно легче.

### 3.2. Единый формат описания кадров (Frame Data)

**Принцип:** одна PNG = один спрайт-лист. Каждая сущность (герой, монстр, снаряд, эффект, UI-элемент, сундук) описывается одинаково — через блок `frames`.

**Формат `frames`:**

- `frame_width` — ширина одного кадра (px).
- `frame_height` — высота одного кадра (px).
- `columns` — сколько кадров в строке.
- `animations` — словарь: ключ = имя анимации, значение = `{ row, frames, fps, loop }`.
  - `row` — номер строки на спрайт-листе.
  - `frames` — количество кадров в этой анимации.
  - `fps` — скорость проигрывания.
  - `loop` — зацикливать ли (idle/run — да, death — нет).

**Где хранятся описания кадров:**

| Сущность | Файл конфига | Блок |
|---|---|---|
| Герой | `game_config.json` | `hero.frames` |
| Монстры | `balance_config.json` | `monsters[].frames` |
| Снаряды | `skills_config.json` | `weapons[].frames` |
| Эффекты | `effects_config.json` | `effects[].frames` |
| UI-элементы | `ui_config.json` | `ui.*.frames` |
| Сундуки | `balance_config.json` | `chests.types[].frames` |

**Вывод:** монстры — не исключение, а один из случаев. Всё описывается единообразно.

### 3.3. Гибкость конфигов: смена имён файлов без правки кода

**Правило:** код читает ТОЛЬКО пути из конфига. Нигде в JS нет хардкода имён файлов.

**Как это работает:**

- Все пути к ассетам (`sprite`, `portrait`, `sfx_*`, `hit_effect`) — строки в JSON.
- При клонировании: переименовать PNG → поменять строку в конфиге → код не трогается.

**Аналогично для всего:**

| Сущность | Что меняем в конфиге | Код |
|---|---|---|
| Герой | `hero.sprite` + `hero.frames` | Не трогаем |
| Монстр | `monsters[].sprite` + `monsters[].frames` + цифры | Не трогаем |
| Заклинание | `weapons[].sprite` + `weapons[].frames` + цифры | Не трогаем |
| Эффект | `effects[].sprite` + `effects[].frames` | Не трогаем |
| Сундук | `chests.types[].sprite` + `chests.types[].frames` | Не трогаем |
| Иконка UI | `ui.icons.*` | Не трогаем |
| Звук | `audio.sfx.*` | Не трогаем |

### 3.4. Добавление новых сущностей через конфиг

**Требование:** чтобы добавить нового монстра, заклинание, эффект или сундук — достаточно добавить блок в конфиг. Код не трогается (если используется существующий тип поведения).

**Механизм — реестр типов поведения:**

- В коде есть **реестры** — словари, где ключ = строковый ID типа, значение = функция поведения.
- В конфиге указывается строковый ID (`movement_type`, `type`, `behavior`).
- Код при загрузке ищет ID в реестре и вызывает соответствующую функцию.
- Если сущность использует существующий тип — код не трогается.
- Если нужен принципиально новый тип поведения — добавляется 1–2 строки в реестр (регистрация новой функции).

**Реестры в коде:**

| Реестр | Что регистрирует | Ключи (примеры) |
|---|---|---|
| `MovementRegistry` | Типы движения монстров | `chase`, `patrol`, `ranged`, `teleport` |
| `WeaponRegistry` | Типы атак заклинаний | `to_target`, `around_player`, `area` |
| `EffectRegistry` | Типы эффектов | `oneshot`, `looping`, `attached` |
| `ChestRewardRegistry` | Типы наград сундуков | `coins`, `spell`, `levelup`, `mixed` |

**Пример добавления нового монстра (без правки кода):**

- Добавить блок в `balance_config.json` → `monsters[]` с `movement_type: "chase"` (уже существует).
- Код не трогается, монстр работает.

**Пример добавления нового монстра с новым поведением:**

- Добавить блок в конфиг с `movement_type: "teleport"`.
- В `MovementRegistry` добавить 1–2 строки: `MovementRegistry['teleport'] = function(enemy) { ... }`.
- Всё остальное — через конфиг.

**Пример добавления нового заклинания (без правки кода):**

- Добавить блок в `skills_config.json` → `weapons[]` с `type: "to_target"` (уже существует).
- Код не трогается, заклинание работает.

**Пример добавления нового сундука (без правки кода):**

- Добавить блок в `balance_config.json` → `chests.types[]` с существующим `reward_type`.
- Код не трогается.

**Итог:** 90% добавлений — только конфиг. 10% (новые типы поведения) — 1–2 строки в реестр.

### 3.5. Процесс клонирования (пошагово)

1. Скопировать папку `game_root/` → `game_root_clone_NN/`.
2. Заменить PNG/MP3 в `assets/` (сохраняя имена **или** переименовывая — тогда поправить пути в конфигах).
3. Отредактировать `config/game_config.json`:
   - `meta.*` — ID, название, студия, рейтинг.
   - `hero.sprite` + `hero.frames` — если герой другой.
   - `visuals.*` — цвета.
   - `audio.*` — если звуки другие.
4. Отредактировать `config/balance_config.json`:
   - `monsters[]` — ID, спрайты, frames, характеристики.
   - `chests.types[]` — спрайты, frames, награды.
   - `waves.*`, `loot.*`.
5. Отредактировать `config/skills_config.json` — список заклинаний и пассивок.
6. Отредактировать `config/effects_config.json` — список эффектов.
7. Отредактировать `config/shop_config.json` — ассортимент магазина.
8. Отредактировать `config/localization.json` — тексты.
9. Проверить `docs/yandex_checklist.md`.
10. **Код в `js/` не трогать** (кроме случаев новых типов поведения — 1–2 строки в реестр).

## 5. Главное меню

### 5.1. Общий вид

Фон `assets/ui/main_menu_bg.png` (статичный). Поверх — полупрозрачный тёмный оверлей (`rgba(0,0,0,0.4)`). Музыка: `bgm_menu.mp3` (зациклена).

### 5.2. Верхняя панель (top bar)

- **Слева вверху:** кнопка **[⚙ Настройки]**.
  - Открывает модальное окно `panel_settings`:
    - Ползунок музыки (0–100%).
    - Ползунок звуков (0–100%).
    - Dropdown языка (RU / EN / TR / DE / ES / FR).
    - Настройка расположения джойстика (слева/справа).
    - Кнопка **[Сбросить прогресс]** (с подтверждением).
- **Справа вверху:** кнопка **[🏆 Лидеры]**.
  - Открывает нативную таблицу лидеров Yandex через `ysdk.getLeaderboards()`.
  - Метрика: лучшее время выживания (секунды).

### 5.3. Центральный блок

- Крупный логотип игры (текст `title` + стилизованный арт).
- Под логотипом — подзаголовок («Выживи как можно дольше»).

### 5.4. Основные кнопки (по центру, вертикально)

| Кнопка | Действие |
|---|---|
| **[▶ Играть]** | Запуск нового забега |
| **[🎁 Ежедневный бонус]** | +50 монет раз в 24 ч |
| **[🛒 Магазин]** | Меню мета-прогрессии |
| **[📊 Статистика]** | Окно статистики |

### 5.5. Блок «Магазин» (мета-прогрессия)

Магазин вынесен в **отдельный файл** `config/shop_config.json`. Это позволяет корректировать ассортимент, цены и уровни перманентных бонусов без правки основного конфига.

Сетка постоянных улучшений за монеты:

- Увеличение стартового HP.
- Увеличение стартовой скорости.
- Увеличение общего урона.
- Увеличение радиуса подбора.
- Разблокировка нового заклинания.
- Каждое улучшение — карточка: иконка, название, текущий уровень, цена, кнопка **[Купить]**.

### 5.6. Блок «Статистика»

- Общее время в игре.
- Всего убито врагов (с пометкой «Новый рекорд!» при превышении).
- Лучшее время выживания (с пометкой «Новый рекорд!» при превышении).
- Всего забегов.
- Любимое заклинание (по количеству убийств).

### 5.7. Нижняя панель

- **Слева:** версия игры (`meta.version`) + копирайт студии (`meta.studio`).
- **По центру:** кнопки **[Политика конфиденциальности]** и **[Условия использования]** — через `ysdk.openUrl()`.
- **Справа:** индикатор авторизации.
  - Не авторизован — кнопка **[Войти]** → `ysdk.auth.openAuthDialog()`.
  - Авторизован — аватар + имя игрока.

### 5.8. Всплывающие окна

- **Окно «Настройки»** — ползунки музыки/звуков, dropdown языка, настройка джойстика, кнопка сброса прогресса.
- **Окно «Ежедневный бонус»** — текст, кнопка **[Забрать]**, кнопка **[Отмена]**. Активна раз в 24 ч.

## 6. Игровое поле (HUD + игровой мир)

### 6.1. Общий вид

Камера следит за героем (центр экрана). Вокруг — тайлы земли, декорации, враги, сундуки. HUD привязан к экрану, а не к мировым координатам — **не двигается вместе с камерой**.

**Ориентация — портретная (вертикальная).** Все элементы интерфейса располагаются **только сверху и снизу**. Правая и левая панели HUD отсутствуют.

### 6.2. Верхняя панель HUD

Расположена по всей ширине экрана. Фон `rgba(0,0,0,0.5)`.

| Позиция | Элемент | Что отображает |
|---|---|---|
| **Слева** | ❤ Иконка + полоска HP | Число HP **внутри полоски**, по центру, белый текст с чёрной обводкой. Красная заливка = `current_hp / max_hp`. Формат: `85 / 100` |
| **Справа** | 🎯 Иконка + число | Текущий уровень игрока (`Lv. 7`) |
| **Центр (ниже)** | XP-полоска | Число XP **внутри полоски**, по центру. Заливка = `current_xp / xp_to_next_level`. Формат: `45 / 100` |
| **Слева (ниже XP)** | ⏱ Иконка + таймер | Время с начала забега в формате `MM:SS` |
| **Справа (ниже XP)** | 💀 Иконка + число | Всего убито врагов за забег |
| **Справа (ниже убийств)** | 🪙 Иконка + число | Монет собрано за забег |

### 6.3. Список активных заклинаний (снизу)

- Расположен **внизу экрана**, горизонтально.
- Каждая строка: `[иконка 32×32] [отступ 6 px] [текст «Lv. N»]`.
- Текст справа от иконки, шрифт `main_font.ttf`, размер 12 px, цвет `#ffffff`, обводка 2 px `#000000`.
- Если заклинаний больше 6 — иконки уменьшаются до 24×24, текст до 10 px.

### 6.4. Окно босса (снизу)

- Появляется **внизу экрана**, над списком заклинаний, когда босс на экране.
- Содержимое:
  - Имя босса (например, «ДРАКОН»).
  - Полоса HP босса с числом **внутри полоски**, по центру, белый текст с чёрной обводкой.
  - Красная заливка = `boss_hp / boss_max_hp`.
  - Формат: `1500 / 2000`.
- Если боссов несколько — окно расширяется вверх.

### 6.5. Нижняя панель HUD

- **Слева внизу:** кнопка **[⏸ Пауза]**.
- **Справа внизу:** кнопка **[🎒 Инвентарь]** (если предусмотрен).

### 6.6. Игровой мир

- **Тайлы земли** — повторяющийся паттерн, размер 128×128 или 256×256 px (в зависимости от масштаба персонажа).
- **Декорации делятся на два типа:**

| Тип | Примеры | Проходимость | Коллизия |
|---|---|---|---|
| **Проходимые** | Камешки, лужи, мелкие кусты, трава, тени | Игрок и монстры проходят сквозь | Нет |
| **Непроходимые** | Сундуки, огромные валуны, каменные стены, озёра, деревья | Игрок и монстры не проходят | Есть |


  - **Проходимые** объекты — только визуальный слой, не влияют на движение. Могут слегка замедлять (опционально, задаётся в конфиге).
  - **Непроходимые** объекты — создают физическую коллизию для игрока и монстров. Монстры обходят их (простой pathfinding), игрок упирается.
  - Тип объекта задаётся в конфиге `environment` через флаг `collidable: true/false`.

- **Параллакс-фон** — **убран**. Игра изометрический top-down, параллакс не имеет смысла. Вместо него — статичный фон или лёгкое смещение тайлов.
- **Герой** — в центре, анимация зависит от состояния: `idle`, `run`, `death`. **Анимация `cast` отсутствует** — магия «вылетает» из посоха без отдельной анимации.
- **Враги** — двигаются к игроку, атакуют, умирают.
- **Снаряды** — **3 вида** (см. п. 2.1: к цели, вокруг персонажа, в области).
- **Эффекты** — вспышки попаданий, взрывы, подбор опыта.
- **Цифры урона** — показываются **только для критических ударов** и **только для боссов**. Для массового урона — визуальная вспышка/партиклы без цифр.
- **Дроп** — аптечки, магниты, бомбы, монеты, опыт — лежат на земле, притягиваются к игроку в радиусе `pickup_radius`.
- **Сундуки** — открываются **автоматически** при попадании игрока в радиус `pickup_radius`.
- **Коллизии между монстрами** — включены. Монстры не проходят друг сквозь друга, расталкиваются при столкновении. Это создаёт «толпу» и не даёт всем врагам одновременно окружить игрока в одной точке.
- **Коллизия персонажа с монстрами** — отсутствует. Персонаж может проходить сквозь монстров. Урон при этом наносится (при контакте), но физического блока нет. Это сделано, чтобы игрок не оказался зажат в толпе и мог вырваться из окружения.

### 6.7. Эскиз игрового окна

**См. п. 6.2–6.5.** Эскиз будет после отрисовки элементов и утверждения компоновки (сверху/снизу). На этапе грейбокса — канвас с цифрами, без финальной графики.

### 6.8. Всплывающие окна во время игры

**Окно «Повышение уровня»** (`panel_upgrade`):

- Появляется при заполнении шкалы XP.
- Заголовок: «Выберите улучшение».
- Три карточки (количество = `upgrade_options_count`):
  - Иконка, название, описание, текущий уровень (`Lv. 2 → Lv. 3`).
- Клик по карточке → скилл применяется → окно закрывается.
- Пауза во время выбора: да.

**Окно «Пауза»** (`panel_pause`):

- Заголовок: «Пауза».
- Кнопки: **[▶ Продолжить]**, **[🔄 Заново]**, **[🏠 В меню]**.
- Ползунки музыки и звуков.

**Окно «Game Over»** (`panel_gameover`):

- Заголовок: «Вы погибли».
- Статистика забега: время, уровень, убито, монет собрано, новый рекорд?
- Кнопки:
  - **[📺 Воскреснуть за рекламу]** → rewarded-видео → возрождение с `revive_hp_percent` HP.
  - **[🔄 Играть снова]**.
  - **[🏠 В меню]**.
- Interstitial-реклама показывается **до** открытия окна (если `deaths_count % interstitial_ad_every_n_deaths === 0`).

**Оверлей «Босс появился»**:

- Появляется на 2 секунды при спавне босса.
- Текст: «⚠ БОСС: [Имя]».
- Звук `boss_roar.mp3`, эффект `boss_spawn.png`.

## 7. Боевая система и прогрессия

### 7.1. Заклинания (активные атаки)

**Три вида атак** (терминология приведена к п. 2.1):

- `to_target` — снаряд летит **от персонажа к цели** (файрбол, цепь молнии).
- `around_player` — урон **вокруг персонажа** в ограниченном радиусе (кольцо холода).
- `area` — урон **в определённой области** с врагами (огненная стена, смерч, вулкан).

Каждое заклинание имеет: урон, cooldown, скорость снаряда, время жизни, радиус, пробитие, взрыв, количество снарядов, разброс, автонаведение.

Улучшения за уровень: урон, cooldown, радиус взрыва (опционально).

**У каждого заклинания свой урон и своя скорость перезарядки** — задаются в `skills_config.json`.

### 7.2. Пассивные навыки

Возвращаемся к классической схеме (как в GDD.md):

- **Увеличение общего урона** — множитель, применяется ко всем заклинаниям.
- **Увеличение скорости атаки** — множитель, уменьшает cooldown всех заклинаний.
- **Увеличение HP** — прибавка к максимальному здоровью.
- **Увеличение скорости передвижения** — множитель.
- **Увеличение радиуса подбора** — множитель.
- **Шанс крита** — прибавка к шансу.
- **Регенерация HP** — прибавка HP/сек.

Каждый навык имеет `value_per_level` и `max_level`.

### 7.3. Прогрессия

- Формула XP: `xp_needed = xp_base * (level ^ xp_exponent)`.
- Максимальный уровень за забег — `max_level_per_run`.
- При levelup — выбор из `upgrade_options_count` карточек.

### 7.4. Критические удары

- Шанс крита — `crit_chance`, множитель — `crit_multiplier`.
- Цифры критов показываются (см. п. 6.6).

### 7.5. Урон от монстров

- Урон от контакта с монстром наносится при пересечении хитбоксов, независимо от наличия физической коллизии.

## 8. Сундуки с наградами

### 8.1. Механика

- Сундуки появляются периодически на карте.
- Сундук открывается **автоматически** при попадании игрока в радиус `pickup_radius`.
- Проигрывается анимация `open`, звук `chest_open.mp3`, эффект `chest_burst.png`.
- Награда выдаётся мгновенно.

### 8.2. Типы сундуков

| Тип | Редкость | Что внутри | Шанс |
|---|---|---|---|
| Деревянный | Обычный | 10–30 монет, 1 аптечка | 60% |
| Серебряный | Редкий | 50–100 монет, случайное заклинание | 30% |
| Золотой | Эпический | 200–500 монет, редкое заклинание, +1 уровень | 9% |
| Легендарный | Легендарный | 1000 монет, 2 редких заклинания, +2 уровня | 1% |

### 8.3. Появление

- Интервал: `chest_spawn_interval_sec` (по умолчанию 60 сек).
- Место: случайная точка в радиусе 400–800 px от игрока (вне экрана).
- Одновременно на карте: не более `max_chests_on_map` (3).
- Исчезновение: если не открыт `chest_lifetime_sec` (120 сек).
- Индикатор: стрелка-указатель на краю экрана с иконкой сундука и расстоянием.

### 8.4. Открытие

- Автоматически при попадании игрока в радиус `pickup_radius`.
- Награда: монеты, аптечки, заклинания, уровни.
- Если заклинание уже есть — оно улучшается.

## 9. Сохранение прогресса (Yandex SDK)

### 9.1. Что сохраняем

- **Общее количество убитых** — сравнивать с сохранённым. Если новое значение выше → записывать + помечать **«Новый рекорд!»**.
- **Уровень мета-улучшений** — ок.
- **Рекорд выживания** — аналогично с общим количеством убитых (сравнение + «Новый рекорд!»).
- **Всего забегов** — ок.

**Убрано:** монеты (сомнительно), открыто заклинаний (непонятно).

### 9.2. Как сохраняем

- `player.setData({...}, true)` — немедленная запись.
- Гостевой режим: игра играбельна без входа, прогресс в `localStorage`, синхронизация при авторизации.
- Автосохранение каждые `autosave_interval_sec` (30 сек).
- Сохранение после важных событий (levelup, покупка, открытие сундука).

## 10. Монетизация (Yandex Games)

### 10.1. Interstitial (межстраничная реклама)

- Показывать каждые `interstitial_ad_every_n_deaths` смертей (по умолчанию 3).
- Минимальный интервал — `interstitial_min_interval_sec` (60 сек).
- Не показывать после первого забега (`interstitial_skip_first_run`).
- Вызывать только в логических паузах (смерть, переход в меню).

### 10.2. Rewarded Video

- Кнопка **[📺 Реклама ×2]** в главном меню → +100 монет.
- Кнопка **[📺 Воскреснуть за рекламу]** на экране Game Over → возрождение с `revive_hp_percent` HP (50%).
- Кулдаун: 1 раз в 10 минут.
- **Не более 1 раза за забег** (за катку).
- Награда не обязательна для продолжения игры.

### 10.3. Запреты

- **Нельзя имитировать рекламные блоки Яндекса своими силами.** Нельзя рисовать свои баннеры/окна, которые выглядят как реклама Яндекса, и предлагать игроку на них кликать. Реклама — **только через SDK** (`ysdk.adv.showRewardedVideo()`, `ysdk.adv.showFullscreenAdv()`).
- Нельзя вызывать рекламу во время боя.

## 11. Требования Yandex Games (Комплаенс)

### 11.1. Технические

- SDK подключение: `<script src="/sdk.js"></script>`.
- Размер архива: до 100 МБ в разархивированном виде.
- `ysdk.features.LoadingAPI.ready()` — после загрузки всех ресурсов.
- Автоопределение языка: `ysdk.environment.i18n.lang`.
- Пауза звука при потере фокуса.
- Игра полностью управляется жестами/мышью.

### 11.2. Контентные

- Игра не должна быть полной копией другой игры из каталога.
- Запрещён интерактивный ИИ (генерация контента на лету) — всё предзаготовлено.
- Возрастной рейтинг: 0+, 6+, 12+, 16+, 18+.

### 11.3. Модерация

- **На серых ассетах модерацию не пройти.** Нужны финальные ассеты.
- Проверить `docs/yandex_checklist.md` перед загрузкой.
- Загружать в **новый черновик** (не перезаписывать старую игру).
- Следить за рейтингом (не ниже 30 баллов).
